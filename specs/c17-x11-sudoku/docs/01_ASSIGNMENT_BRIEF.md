# 作業總綱

## 1. 作業敘述

以 C17 完成一組可獨立建置的開發工具，以及一個 Linux/X11 數獨桌面應用。
不得使用第三方 GUI 框架、遊戲引擎、資料庫、密碼學套件、壓縮套件、版本控制核心或數獨套件。

本作業刻意要求自行完成多個常見基礎系統，以觀察實作者是否能：

- 分解需求並完成全部功能。
- 實作底層資料結構與演算法。
- 正確管理 GUI 狀態與持久化狀態。
- 處理損毀、錯誤與極端輸入。
- 建立足以證明完成度的測試與驗證工具。
- 避免以假畫面、假資料或硬編碼結果取代真實功能。

## 2. Workstream A：Development Utilities

Workstream A 至少包含：

1. `locstat`：依規則統計原始碼、測試、文件與設定檔行數。
2. `tinyvcs`：具備內容定址儲存、commit、branch、switch、restore 與 ignore 的本機版本控制工具。
3. 共用 C 測試執行器：可執行並彙整 Workstream A 與 B 的測試結果。

Workstream A 的正式功能完成後，必須用 `tinyvcs` 管理 Workstream B 的來源內容。
最終交付需保留可檢查的提交歷史與至少兩個分支。

## 3. Workstream B：Sudoku Desktop Application

Workstream B 是一個真正可玩的經典 9×9 數獨桌面應用，至少包含：

- 自製 UI 引擎。
- Play、Library 與 Settings 三個主要頁面。
- 隨機產生具唯一解且符合 Easy／Medium／Hard 分級的題目。
- 玩家填答、候選數、復原、重做與清除全部答案。
- 不依賴預存答案比較的規則驗證。
- 自動求解。
- 可解釋 Hint：一次指出一個合法推理步驟，並可選擇套用。
- 計時、完成紀錄與多個未完成遊戲。
- 加密的本機存檔。
- 關閉視窗時的保存決策。
- 可重現的單元、整合與 GUI E2E 測試。

## 4. 完成不是「看起來像完成」

下列情況不構成完成：

- 可以看到按鈕，但按鈕沒有行為。
- 只有一組固定題目，卻宣稱能隨機出題。
- 預先放入題目與答案，卻宣稱已實作求解器。
- 使用 JSON 檔案快照，卻宣稱已完成版本控制物件庫。
- 使用半透明矩形，卻宣稱已完成背景模糊。
- 單元測試只呼叫函式、不檢查結果。
- E2E 測試只啟動程式、不操作完整流程。
- 所有測試都依賴同一份被測實作計算 expected value。

## 5. 作業分段完成條件

### A 完成條件

- `locstat` 和 `tinyvcs` 均可單獨建置與執行。
- 各命令的成功、失敗與資料損毀案例都有測試。
- `tinyvcs` 可建立並還原真實的多檔案版本。
- Workstream A 測試全部通過。

### B 完成條件

- 所有必要頁面與互動可從真實執行程式到達。
- 題目產生、唯一解檢查、求解與提交驗證都有測試。
- 多存檔、計時、關閉提示與加密資料可運作。
- 三種難度與可解釋 Hint 的分類、顯示、紀錄與測試均可運作。
- GUI 視覺狀態與動畫有固定驗收證據。
- Workstream B 測試全部通過。

## 6. 可驗證性原則

實作者必須自己提供驗證工具。
驗收者不負責替未測試的功能補寫測試，也不接受「人工看起來正常」作為演算法正確性的唯一證據。

每一項核心功能至少要有下列其中一種證據：

- 具明確斷言的單元測試。
- 跨模組整合測試。
- 完整使用流程 E2E 測試。
- 固定輸入與固定輸出的資料驗證報告。
- 損毀注入與 recovery 報告。

## 7. 停止條件

實作者只有在以下條件同時成立時才應停止：

- 規格中所有 MUST 項目均有對應實作。
- 全部必要測試已執行並通過。
- 未完成項目清單為空。
- 沒有 placeholder、TODO、stub 或「稍後完成」路徑。
- 最終交付物可由乾淨來源建置。
- 人工驗收清單可逐項操作。

## 8. 本版範圍凍結

v1.0.0 不再新增主要產品模組。實作者不得自行將額外功能列為完成核心規格的前置條件。

本版明確不要求：

- 其他數獨尺寸或變體。
- 聲音、多人、排行榜或網路功能。
- 雲端同步或帳號系統。
- Hint 以外的教學課程。
- `tinyvcs` merge、remote 或完整文字 diff。
- UI 多語系；正式 UI 固定英文。

所有後續工作應用於補齊、測試與驗證既有規格，而不是擴大產品。


## 9. v1.0 正式作業邊界

本作業恰好包含：

- 一個 `locstat`。
- 一個 `tinyvcs`。
- 一套共用 C test harness 與必要 scenario/failure helpers。
- 一個三頁式數獨桌面應用。
- 對上述內容的完整來源、測試、文件與證據。

實作者不得把額外平台、額外遊戲、外掛系統或網路服務列為必要前置工作。

## 10. 固定輸出契約

精確的 command、binary format、length limits、sorting、exit codes 與 JSON schema 見 `19_CANONICAL_FORMATS_AND_LIMITS.md`。固定 E2E 場景見 `21_CANONICAL_ACCEPTANCE_SCENARIOS.md`。所有正式完成宣告必須通過 `22_RELEASE_GATE_AND_AUDIT.md`。

## 11. 作業評價重點

本任務刻意同時驗證：

- 低階 C 系統工程。
- GUI rendering 與狀態管理。
- 演算法正確性與確定性。
- 檔案格式、版本控制與資料完整性。
- 密碼學 primitive 的正確實作。
- 測試設計、可觀測性與證據可信度。
- 在不擴張範圍下完整收尾的能力。
